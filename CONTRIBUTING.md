# Contributing to Enkryptit!

First of all, thank you for your interest in contributing to Enkryptit!

Whether you're reporting a bug, suggesting an improvement, reviewing code, improving documentation, or submitting a pull request, your contribution is appreciated.

## Project Philosophy

Enkryptit! is a security-oriented file & folder encryption manager written in Rust.

Because the project handles cryptographic operations and sensitive user data, correctness, maintainability, and security are valued above development speed. Every contribution should prioritize reliability and clear design over feature count or implementation shortcuts.

## Reporting a secure break

When reporting a break, **don't** open an issue. Contact me on discord (`vram_ram`). Please try to :

* Explain in details the break.
* Be clear.
* Don't share it.

## Reporting Issues

When opening an issue, please try to provide:

* A clear description of the problem.
* Steps to reproduce the issue.
* Expected behavior.
* Actual behavior.
* Relevant logs, screenshots, or error messages.
* Platform information (OS, Rust version, etc.).

Security-sensitive vulnerabilities should not be disclosed publicly before being reviewed by the maintainer.

## Pull Requests

Before submitting a pull request:

1. Ensure your changes solve a clearly identified problem.
2. Keep pull requests focused and reasonably small.
3. Update documentation when necessary.
4. Test your changes whenever possible.
5. Write clear commit messages and PR descriptions.

Large architectural changes should ideally be discussed in an issue before implementation.

## Security Considerations

This project uses modern cryptographic primitives and aims to follow established security practices.

Contributors should:

* Avoid introducing custom cryptographic constructions.
* Avoid modifying cryptographic parameters without justification.
* Clearly document security-related decisions.
* Prefer established standards and audited libraries whenever possible.

Security-related pull requests may be subject to additional review.

## AI-Assisted Contributions

Moderate and responsible use of AI-assisted development tools is permitted.

However, contributors are expected to fully understand, review, and take responsibility for any code they submit.

Pull requests that appear to be largely generated by autonomous coding agents with little or no meaningful human oversight may be rejected at the maintainer's discretion.

Contributors should be able to explain:

* The purpose of their changes.
* The implementation details.
* Any security implications introduced by the modification.

For Enkryptit!, human review and security awareness take precedence over development speed.

## Code Style

General expectations:

* Follow idiomatic Rust practices.
* Prefer readable and maintainable code.
* Avoid unnecessary complexity.
* Add comments when the intent is not obvious.
* Keep public APIs consistent and well documented.

Additional coding guidelines may be added as the project evolves.
